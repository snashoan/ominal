### Getting started

- Start with one clear outcome, then refine the design as you test.
- Keep chat as home; open extra tools only when the task needs them.
- Sign in to your preferred provider before starting your first task.
- Attach project files to keep each chat grounded in its workspace.

### Computer use

- Open Screen when a task needs a browser, desktop app, or form.
- Use touch for manual steps, then return to chat to continue the task.
- Let the screen resize around the keyboard before entering text.
- Keep each chat tied to its own terminal and working files.

### Agents

- Give each chat one goal so its work stays focused and resumable.
- Run independent jobs in parallel when they do not share changing files.
- Ask for a checkpoint before leaving a long build or installation.
- Keep long jobs in a saved session so disconnecting does not stop them.

### Recovery

- Check the latest checkpoint before retrying an interrupted task.
- Reconnect the device before rebuilding when only installation failed.
- Resume a saved session instead of starting the same job again.
- Verify build, sign-in, screen, and chat before calling the task done.

- Work commonly moves from architecture discussion into rapid device testing.
- Long builds are expected to survive terminal and network disconnections.
- Chat, terminal, files, and graphical computer use form one workflow.
- Frequent checkpoints, installs, screenshots, and retries guide iteration.
- Completion is judged through working behavior on a real device.
